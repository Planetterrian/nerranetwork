> **New York just banned AI chatbot toys for kids for the next five years.**
Today we're looking at a new safety rule that keeps AI chatbots away from young children, a behind-the-scenes look at how AI can double-check its own work, and a fun new ChatGPT feature that turns ordinary days into adventures. ### The Big Story
New York governor Kathy Hochul signed a law that stops stores from selling AI chatbot toys for the next five years. These toys are physical objects that talk back to kids using AI, and the state wants to pause their sale while researchers study how they affect children. Think of it like putting a temporary stop sign on a new kind of playground equipment until everyone figures out if it's safe. The rule comes after studies showed some chatbots can share inappropriate content or affect how kids learn to talk with real people. New research from Common Sense Media reveals troubling safety failures, including exposure to inappropriate content and risks to emotional development. For teens and younger kids, this means the AI toys you might see advertised around the holidays won't be on shelves in New York for a while. It also sends a signal to companies that safety rules are coming for any product aimed at children. Parents and kids everywhere can use this as a reminder to talk openly about what AI tools are doing when they chat with them. The five-year length gives researchers time to gather real data on how these toys shape conversations and feelings. Right now there is no free demo to try because the point of the story is the pause itself, but you can read the full law on the New York state government website if you're curious about how these rules get written. This change matters because it shows governments are starting to treat AI toys the same way they treat other products that can shape how young people grow up. The ban applies to sales inside the state, so online sellers shipping to New York addresses must also follow it. Companies making these toys will need to redesign or wait before they can sell again in that market. Source: [engadget.com](https://www.engadget.com/2328996/new-york-state-bans-ai-chatbot-toys-for-kids/)

### Explain Like I'm 14
You know how when you're texting a friend and you finish a sentence, you sometimes glance back to make sure you didn't type the wrong word or leave something out? Now picture an AI that writes a whole block of code for a big project, then uses a second copy of itself to read that code line by line and flag any spots where the two versions don't match. The first AI is trying to build something new, while the second one acts like a careful proofreader that only cares about catching differences. Because the proofreader version never changes its own rules, it can spot mistakes even when the builder version gets creative or unpredictable. This back-and-forth lets the team move a live system from one programming language to another without turning the service off for users. In the end the new version runs faster and uses less power, all because the AI had a reliable way to check its own homework instead of hoping everything worked on the first try. The cool part is that the same idea could help future AI tools become more trustworthy when they work on real, important tasks. Many problems have a generator–verifier gap: it’s often far easier to verify that a solution is correct than to come up with one. Sudoku is a classic example. It’s simple to check the solution (just count the numbers in each row, column, and box), but finding that solution can take a long time. Many ambitious Claude projects have relied on this gap: formalizing proofs in mathematics or migrating large, well-tested codebases are tasks Claude can take on as long as it has a reliable way to verify its work. But as Claude has become more capable, it’s begun to take on projects in live systems, where generating the work is easier than verifying it. In these systems, users often rely on edge cases and quirks that fall outside the test suite, and it’s hard to write a definition of “correct” that covers everything. Without a reliable way to check Claude’s work, the migration of a live system is hard to trust—however quickly Claude can generate the code for it. We ran into this problem when we migrated our Messages API from Python to Rust. This API is the primary way that customers—as well as our own apps, like Claude Code and Cowork—reach Claude. From early 2024 to fall 2026, API traffic grew roughly 1,800 times. Rust would allow us to use far less CPU per request. Claude wrote a first version of the API’s core request path in about a week. But building trust in the migration required us to find a way to verify that our Rust API was at parity with our production API. This proved hard for several reasons, including that the Python API continued changing throughout the migration, so parity was a moving target; Claude can reply nondeterministically to the same request, so a difference between two outputs didn’t necessarily mean a bug; and we couldn't read customer requests, so we weren't able to easily see where the two versions diverged. In this post, we share how we turned the production Messages API itself into a verifier—and how that helped us test the new Rust version on production traffic, find where it differed, and automatically dispatch agents to fix those differences. This allowed us to ship an API on Rust that uses about 70% less CPU per request and cuts median time to first token by about 20% without ever taking the service offline or freezing feature development. Source: [anthropic.com](https://www.anthropic.com/research/migrating-api-to-rust)

### Cool Stuff & Try This
**Turn an ordinary day into a movie scene**
ChatGPT now has a feature called "Make a Day Do Anything" that helps you imagine small, fun twists on normal routines. It takes a regular activity like walking to school or eating lunch and suggests ways to make it feel more like an adventure or story. This is great for anyone who wants a quick creative spark without needing to learn prompts or settings. You can try it right now by opening ChatGPT on your phone or computer, typing "Make a Day Do Anything" followed by something you do every day, like "walking the dog after school," and seeing what ideas it gives back. No account is needed for basic use, and the results stay light and playful. It's a simple way to practice creative thinking while seeing how AI can turn everyday moments into something more interesting. The feature works by taking your short description of a routine and expanding it into a sequence of small, story-like moments you could actually do. For example, it might turn a bus ride into a treasure hunt where every stop has a clue. Because the suggestions stay grounded in real life, you can pick one or two ideas and try them the same day. Teens who like storytelling or journaling will find it especially useful for turning boring commutes into quick creative exercises. The tool is available inside the regular ChatGPT interface, so you can switch between normal questions and this playful mode without learning anything new. Source: [x.com](https://x.com/OpenAI/status/2125635627341561995)
