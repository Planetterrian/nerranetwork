Claude wrote a first pass of a live customer doorway in about a week, Anthropic shares, then needed proof the new code matched the old.

That doorway is called the Messages API, which is the main path customers use to reach Claude, along with Anthropic's own apps such as Claude Code and Cowork.

Checking a finished Sudoku grid is the easy part, because you only count whether each row, column, and box has the right numbers.

Finding the solution in the first place can take a long time.

A lot of hard problems work that way, and people call it a generator-verifier gap, meaning it is often simpler to check an answer than to invent one.

Claude has used that gap on jobs like turning math arguments into strict proofs, and on moving big, well-tested piles of code, as long as a checker could say yes or no.

Live systems flip the difficulty, because writing new code can be the easy step, while deciding what "correct" even means is the hard one.

Users lean on odd little quirks that tests never listed, so a checklist cannot cover every case.

Anthropic ran into that when it moved the Messages path from Python to Rust, two programming languages, with Rust chosen because it can spend far less computer effort on each request.

Traffic through that path grew roughly one thousand eight hundred times from early two thousand twenty-four to fall two thousand twenty-six.

Trust was still hard, because the Python version kept changing, so the target moved while they worked.

Claude can also answer the same question two different ways, so a mismatch is not always a bug.

The team could not read customer messages, so they could not hunt for gaps by looking at what people typed.

They turned the live Messages path itself into the checker, ran the new Rust version on real traffic, spotted where the two disagreed, and sent extra AI helpers, called agents, to fix those spots.

The Rust version now uses about seventy percent less computer effort per request, and the middle-of-the-pack wait before the first scrap of a reply appears is about twenty percent shorter.

Users kept chatting the whole time, and new features did not freeze while the swap happened.

A builder that invents, plus a checker that only hunts for differences, is a lot of the reason that swap could be trusted.
