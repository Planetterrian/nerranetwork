**Microsoft says the 74-country Microsoft 365 outage is fixed, and officials separate it from the FAA ground stop: The Federal**
Microsoft said it has restored Microsoft 365 and Copilot after users in 74 countries were unable to reach services for more than 24 hours. The company blamed an issue during an earlier network capacity upgrade that surfaced after a recent network change, and described it as a technical fault not related to cyber or AI agents. The Federal reported that Teams chats and meetings returned before some Exchange Online calendar features, that OpenAI and Anthropic's Microsoft 365 connectors were affected, that IndiGo and Akasa Air reported email problems while Air India rerouted email and flights continued, and that NHS staff in the UK turned to paper records. GeekWire reported that Homeland Security Secretary Markwayne Mullin and Transportation Secretary Sean Duffy said Friday's nationwide ground stop was aging FAA telecom gear, not Microsoft and not the FAA's SMART traffic-planning tool. Duffy said unstable radar and communications data began at 12:36 p.m. Pacific, the FAA reopened US airspace at 5:15 p.m. Pacific, new IP switches held while older hardware on 1980s copper lines did not, and he wants $50 billion after the administration asked Congress for an additional $30.1 billion. Microsoft said it had no indication the ground stop was related to its disruption and that a full post-incident report will follow the review. Microsoft said in January that it had more than 450 million paid commercial Microsoft 365 subscriptions. Source: [thefederal.com](https://thefederal.com/category/business/microsoft-fixes-global-outage-affecting-microsoft-365-and-copilot-across-74-countries-262900) Source: [geekwire.com](https://www.geekwire.com/2026/dhs-chief-sees-no-microsoft-link-to-faa-ground-stop-says-possible-ai-role-being-investigated/)

**OpenFold3-preview lands on SageMaker JumpStart for structure prediction: Amazon Web Services**
Amazon Web Services published a way to deploy OpenFold3-preview from SageMaker JumpStart, an open-source all-atom model from the OpenFold Consortium and the AlQuraishi Lab at Columbia University, released under the Apache 2.0 license. The endpoint predicts joint 3D structures of proteins, DNA, RNA, small-molecule ligands and the complexes they form, and it runs with network isolation so sequences stay in the customer's account. A real-time SageMaker request is capped at 60 seconds, so this model uses asynchronous inference with an invocation timeout of up to one hour, and the endpoint can scale to zero instances when the queue is empty. Source: [aws.amazon.com](https://aws.amazon.com/blogs/machine-learning/openfold3-on-amazon-sagemaker-jumpstart-predict-biomolecular-structures/)

**Claude turns on by default for unset UK Copilot tenants on December 9: Mezha**
From December 9, UK organizations that have not chosen a setting will have Claude enabled by default in Microsoft 365 Copilot, while EU organizations stay opted out unless an administrator turns it on. Message Center post MC1546435, as reported by Mezha and Notebookcheck, treats an unchanged setting as opting in. Microsoft says Claude models in Copilot, Researcher, Copilot Studio and the Power Platform are currently excluded from the EU Data Boundary, and The Register reports that Anthropic processes that data in the US. The UK is outside the boundary, so Microsoft is dropping the exception there and retiring the option to allow Claude only in Copilot inside the Microsoft 365 apps. UK administrators who want Claude disabled, or limited to specific users and groups, must select that before December 9; only AI administrators and global administrators can make the change. Models with data retention, including Claude Fable 5 and Claude Mythos 5, stay separate under Anthropic's own terms, which keep most inputs and outputs for up to 30 days, and administrators must enable those models themselves. The notices cover managed work accounts, not Microsoft 365 Personal or Family. Source: [mezha.net](https://mezha.net/eng/news/mezha-84aa3f414683a4191d6ffd08_microsoft_to_enable/) Source: [notebookcheck.net](https://www.notebookcheck.net/Microsoft-365-Copilot-turns-on-Claude-for-UK-tenants-on-December-9.1449506.0.html)

### The Thread: Cost per solved task
NVIDIA server version 0.3.0 of NeMo Switchyard is the open-source library Amazon's sample uses to choose which Amazon Bedrock model answers a coding agent. The sample installs switchyard-server 0.3.0 from crates.io and runs LiteLLM image version 1.102.0, both in one container on Amazon Elastic Container Service on AWS Fargate in private subnets. Amazon says NVIDIA documents that server release as a demo and evaluation component, and Amazon calls the integration experimental sample code, not a production deployment.

A coding agent works in tasks. The developer asks for a change; the agent reads files, edits code, and runs tests until the work is done. One task can take a few model calls or dozens. Token price does not equal task price, because the bill depends on how many turns a model needs, how much history each turn replays, and how often a run is retried or never finishes. Every attempt is paid, including attempts that never finish. Amazon's score is cost per solved task: total cost of the runs divided by the number of runs whose tests pass.

The library supports two strategies through LiteLLM. Stage routing reads recent tool activity and results in the history, so the agent must send the full conversation, then picks between a capable model and a lower-cost efficient model. Random routing picks from the configured models, with optional weights, for splits and comparisons. Neither strategy calls a judge model. LiteLLM has also shipped a native Switchyard stage router as an auto-router. Deployment in the sample uses the AWS Cloud Development Kit, and Amazon tells customers to clear the design with security and legal teams and to test it in a non-production account first.

Amazon hosts the gateway and the models; NVIDIA supplies the chooser. The agent sends an OpenAI-compatible request with the model field set to switchyard and a shared gateway key. Only the IPv4 range the deployer allows can reach the hostname, which sits on a load balancer with an AWS Certificate Manager certificate. AWS WAF applies IP-reputation, known-bad-input, and per-IP rate limits. The load balancer forwards only three paths, chat completions, models, and a health check, and returns 404 for every other path. LiteLLM checks the key, the plugin picks the model, and the call goes out through the Bedrock Converse or ConverseStream API on the task's own identity role, via a runtime interface endpoint so the traffic stays on Amazon's network. The header x-litellm-model-name names the model that answered.

The split of work is the change. Amazon gets a harness that compares a routed group with single-model baselines on a customer's own workloads, which is how the post says to judge the router. NVIDIA gets its library in the request path of agents that already speak a common format, without operating the gateway or the capacity those agents consume. The benchmark runners in the sample are the step the post actually specifies for deciding whether that split is worth keeping. Source: [aws.amazon.com](https://aws.amazon.com/blogs/machine-learning/route-coding-agent-requests-to-the-right-model-on-amazon-bedrock-with-nvidia-nemo-switchyard/)
