NVIDIA and Amazon meet in one sample router, and the library's server version is zero point three point zero. NeMo Switchyard is what Amazon's post uses to pick which Amazon Bedrock model answers a coding agent.

The sample installs that server from crates dot io and runs LiteLLM image version one point one hundred two point zero, both in one container on Elastic Container Service on Fargate, in private subnets. Amazon says NVIDIA documents that release as a demo and evaluation piece, and Amazon calls the integration experimental sample code, not a production deployment.

A coding agent works in tasks, not in single calls. The developer asks for a change. The agent reads files, edits code, and runs tests until the work is done. One task can take a few model calls or dozens. Token price is not task price, because the bill depends on how many turns a model needs, how much history each turn replays, and how often a run is retried or never finishes.

Every attempt is paid, including the ones that never finish. Amazon's score is cost per solved task: total cost of the runs, divided by the number of runs whose tests pass.

Two strategies sit in the LiteLLM integration. Stage routing reads recent tool activity and results, so the agent has to send the full conversation, then picks a capable model or a lower-cost efficient one. Random routing picks from the configured models, with optional weights, for splits and comparisons. Neither strategy calls a judge model.

LiteLLM has also shipped a native Switchyard stage router as an auto-router. The sample deploys with the AWS Cloud Development Kit. Amazon tells customers to clear it with security and legal teams and to test in a non-production account first.

Amazon hosts the gateway and the models. NVIDIA supplies the chooser. The agent sends an Open A I compatible request with the model field set to switchyard and a shared gateway key. Only the IPv4 range the deployer allows can reach the hostname, on a load balancer with a Certificate Manager certificate. AWS WAF applies IP reputation, known-bad-input, and per-IP rate limits.

The load balancer forwards only three paths, chat completions, models, and a health check, and returns a four-oh-four for every other path. LiteLLM checks the key, the plugin picks the model, and the call goes through Bedrock Converse or ConverseStream on the task's own identity role, via a runtime interface endpoint, so inference stays on Amazon's network.

The header x-litellm-model-name names the model that answered.

Amazon gets a harness that compares a routed group with single-model baselines on a customer's own workloads, which is how the post says to judge the router. NVIDIA gets the library in the path of agents that already speak a common format, without operating the gateway or the capacity those agents consume.

The benchmark runners in the sample are the step the post specifies for deciding whether that split is worth keeping.
