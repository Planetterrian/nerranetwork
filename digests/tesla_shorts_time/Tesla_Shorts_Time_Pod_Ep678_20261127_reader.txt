Custom code aimed at one specific chip cluster can raise how much of that hardware actually works from the low forties percent range into the low fifties, without buying new machines.

Meta's Llama three job on sixteen thousand H100 chips reached only thirty-eight to forty-three percent of theoretical math peak, and Google's PaLM landed at forty-six percent.

Lambda's tuned stack on GB200 hardware took a comparable workload from twenty-nine percent to fifty-three percent.

Gaps like that start to bite when a cluster reaches two hundred twenty thousand chips, because one more point of utilization is about two thousand two hundred chips you never have to buy or keep powered.

That arithmetic is why xAI rebuilt training and inference in C and C++ instead of remaining inside PyTorch or JAX.

Each extra software layer between the model description and the silicon burns cycles that could have been matrix math, and when thousands of chips pass partial results around, those layers stack up.

Code written once for the exact interconnect and memory layout of a GB300 cluster strips that overhead where the waste is largest.

Tesla made a similar call in two thousand nineteen, leaving Nvidia's off-the-shelf self-driving computer for its own FSD silicon.

The point was not a faster single chip; it was deleting every interface between the neural network and the silicon that would run it at volume.

xAI's rewrite applies that same idea on the software side.
