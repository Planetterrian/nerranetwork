updates are expected in that chat GPT for healthcare offering. Let me pop the hood on those external
sandboxes, because the design decision is to keep the agent's own credentials outside
the execution environment.
Untrusted code running inside never sees keys, and it cannot touch agent configs or logs.
Operators shrink the blast radius of a compromise by putting identity material on one side of that
boundary and the guest process on the other.
Configuration files and execution logs stay on the host, so a sandbox process cannot read or
overwrite them.
The complete network disablement inside the sandbox is workable because the model endpoint
is reached through a host side HTTP proxy rather than direct outbound sockets.
That proxy can enforce host allow lists and do credential replacement, so model calls
still go through while the guest stays off the open network.
The same pattern supports running thousands of sandboxes on a single host without copying
credentials into every container image.
The engineering rule is to use it for network restricted credential-free agent runtimes
at high density on one machine, and not to use it when a model call has to leave through
a direct outbound socket instead of the host side proxy.
