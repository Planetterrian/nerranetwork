OK, let's pop the hood on tool schema adherence in frontier models.

Newer models are not automatically better at tool use because schema adherence is a separate capability that can regress even as reasoning improves.

The core issue appears when models trained heavily on one vendor's edit-tool schema begin emitting extra invented keys inside nested arrays.

The harness rejects the call even though the intended edit is correct.

This adds a retry loop that costs both latency and tokens.

The failure rate rises with the strongest models in the family rather than falling.

Reinforcement learning on the vendor's own harness improves performance inside that harness but reduces robustness on third-party schemas.

Teams therefore face a concrete choice between adopting the vendor's native tool format and accepting lock-in or maintaining multiple parallel tool definitions and routing calls by model family.

The regression often surfaces only after production agents have already been upgraded to the newest checkpoint.
