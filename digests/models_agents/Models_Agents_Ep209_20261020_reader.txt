Web pages wrap the useful bits inside navigation, scripts and ads that agents then strip at token cost, so let me pop the hood on llms.txt, the curated Markdown file meant to skip that parse.

The proposal puts one file at the site root that gathers expert-level summaries and links to key pages, and that file is the map an agent reads first.

Context windows are still finite, so every token spent chewing chrome is a token that never reaches the answer.

A clean Markdown map lets the agent judge relevance before it fetches full pages, which is the step that used to dump a whole human layout into the prompt.

The v2 revision added standard link relations so the agent does not have to guess the URL.

Those relations are rel alternate with type text slash markdown, and rel describedby.

OpenAI, Anthropic and Gemini already publish their developer docs this way, and documentation platforms generate the file automatically.

The engineering tradeoff is maintenance overhead versus retrieval quality.

Sites that keep the file current see agents land on the right information faster, and a stale file is just another outdated asset sitting at the root.

Publish one when you already maintain high-quality Markdown documentation and you want coding agents or retrieval systems to consume it reliably; skip it when nobody will update the map.
