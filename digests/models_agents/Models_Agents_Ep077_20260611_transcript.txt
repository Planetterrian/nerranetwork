The open questions around US and EU regulatory paths and standardized testing now have specific
timelines attached through the new fellowship and evaluation projects. Okay, let's pop the hood
on agent state persistence. Most people picture agent memory as a simple append-only log. In practice,
the design choices around durability, query speed, and consistency turn expensive fast.
Long-running agents need both short-term scratch base and durable cross-session facts.
Mixing the two either drops context or drives storage costs through the roof. A production stack
therefore keeps an in-memory working set for the current run and a separate index store that mixes
vector and relational data for facts that survive restarts. Adding the second layer adds 30 to 80
milliseconds per tool call for serialization and indexing. It also avoids replaying every prior
step on every restart. The trade-off shows up once agents pass roughly 200 tool calls in one session.
After that point, the cost of keeping everything in context exceeds the cost of selective persistence.
Teams should start with a simple key value layer and add vector search only after they see repeated
lookups of the same facts across sessions. Most early agent workloads never hit that threshold.
