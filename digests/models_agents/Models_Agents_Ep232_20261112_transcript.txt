Past roughly 20,000 tokens, long-running agents pop the hood on context rot.
ThoughtWorks explains, as new tokens dilute the system prompts relative weight inside a growing window.
Attention and Transformers follows a U-shaped pattern that favors the very start and very end of the sequence,
while the middle receives sharply lower weight.
Once a long-running agent accumulates tool outputs, reasoning traces, and sub-agent replies,
the original constraints drift into that low attention zone and stop influencing generation.
The mechanical fix is to move critical rules out of the single context window entirely.
Store them in persistent external memory, retrieve them at every step,
and re-inject them as structured context rather than relying on positional attention.
Periodic summarization or hierarchical task graphs further reduce noise by compressing history
while preserving goal structure.
Teams that keep the system prompt static and let the context grow past roughly 20,000 to 50,000 tokens
see the highest drift rates, so the safeguard is to treat the prompt as a short, high-priority
prefix and treat everything else as queryable memory.
This approach belongs on any agent expected to run more than a few dozen turns or handle
conflicting sub-goals because simply lengthening the context window only delays the same
attention decay.
