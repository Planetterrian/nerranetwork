End-to-end speech-to-speech models have no discrete tokens for structured tool calls, so let's pop the hood on why production voice agents still split the work.

A frontend duplex speech-to-text model listens and emits a delegation token when it detects a tool need.

That frontend then streams the automatic speech recognition, or ASR, transcript to a separate text LLM backend that actually runs the function call.

Tool results return through a lightweight prefill-and-repeat path, and the frontend turns them into spoken audio without breaking natural turn-taking.

The split adds roughly fifty to one hundred milliseconds of coordination latency.

Full interruption handling stays intact, and teams can swap in any text LLM for the tool logic.

Full-duplex benchmarks show ninety-two to ninety-seven percent tool-call recall.

End-to-end audio latency stays under eight hundred milliseconds on current hardware.

A cascaded streaming pipeline using Deepgram for speech-to-text, vLLM-served LLMs with function calling, and ElevenLabs for text-to-speech measured seven hundred fifty-five milliseconds time-to-first-audio in best-case tests.

The modular design also supports Monte Carlo sampling for Shapley-value analysis across hundreds of agent-tool configurations on benchmarks such as MMAU and MMAR.

The frontend-backend pattern is the one to use when the agent must call external APIs or keep compliance logs, and pure end-to-end models remain preferable only for simple conversational voice where no external state is required.
