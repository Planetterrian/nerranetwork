Bien, plongeons dans les mécanismes de défense du mode auto.

Tout le monde considère le mode auto comme un simple interrupteur de sécurité, mais la réalité technique est un ensemble de vérifications d’exécution en couches et de modèles de politique qui fonctionnent en parallèle de la boucle principale de l’agent.

Le mécanisme central remplace les invites d’approbation utilisateur par un modèle secondaire toujours actif qui évalue les actions proposées par rapport à un ensemble restreint de schémas interdits avant toute exécution d’outil.

Cela ajoute une latence mesurable, environ un passage avant supplémentaire par décision, mais élimine la fatigue de confirmation qui pousse les humains à approuver quatre-vingt-six pour cent des commandes nuisibles dans les tests rapportés.

La défense est plus efficace lorsque le modèle de politique n’a pas accès au même contexte non fiable que l’agent principal, créant une barrière d’information qui empêche de nombreuses instructions injectées d’atteindre l’étape de décision.

Des compromis apparaissent à grande échelle : le modèle de politique doit rester suffisamment petit pour maîtriser les coûts totaux, tout en étant assez grand pour détecter de nouvelles formulations d’attaque, et l’écart entre ces deux tailles est là où les onze pour cent d’attaques restantes passent encore.

L’approche suppose également que l’ensemble des actions dangereuses peut être énuméré à l’avance ; les agents de codage ouverts capables d’installer des packages arbitraires dépassent rapidement cette hypothèse.

Lorsque le modèle de politique est volontairement maintenu plus petit que l’agent principal, les attaques par formulation nouvelle deviennent plus difficiles à bloquer sans augmenter les taux de faux positifs qui frustrent les utilisateurs.

Les équipes devraient adopter ce schéma uniquement si elles peuvent assumer le coût d’inférence supplémentaire et si l’ensemble d’outils de leur agent est suffisamment restreint pour que les actions interdites puissent être énumérées à l’avance ; pour les agents de codage ouverts, la même approche devient rapidement incomplète sans bac à sable supplémentaire.

Une étape pratique suivante consiste à exécuter le modèle de politique sur une instance distincte et plus petite afin que, même si le contexte principal est empoisonné, la couche de décision reste propre.
