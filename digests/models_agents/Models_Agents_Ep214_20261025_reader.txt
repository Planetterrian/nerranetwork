Millisecond startups are what you see when you pop the hood on OS-level sandboxing that pins a profile to the process at launch.

Seatbelt on macOS and bubblewrap on Linux pin lightweight filesystem and network rules onto that process at launch.

Most agent tools only need a short list of paths: a workspace directory to read, a temp folder to write, or a handful of outbound ports.

On macOS, Seatbelt's built-in profile language spells out allow and deny rules covering file metadata, network sockets, and system calls.

On Linux, bubblewrap uses mount namespaces and seccomp filters, then drops privileges once setup is done.

Write the profile too loose and the agent still reaches unexpected resources; write it too tight and honest tool calls die with opaque permission errors.

Startup latency falls to milliseconds.

Memory overhead sits at a few megabytes per agent, enough to pack hundreds of concurrent workers onto a single node.

Network rules that skip DNS resolution and localhost services will break tool calls the agent is allowed to make.

The fit is a known agent workload on a trusted host OS; container isolation remains the better cage when the agent runs untrusted third-party code or when the same cage must work on macOS, Linux, and Windows.
