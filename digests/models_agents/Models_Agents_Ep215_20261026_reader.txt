Additional agent memory frameworks will likely adopt live per-user stores with explicit side-effect gating.

Frozen draft stores start going stale the moment user behavior drifts, so let's pop the hood on speculative decoding with live per-user memory.

Speculative decoding already reuses past token sequences as drafts, which is how a model guesses several tokens ahead and then verifies them.

Most deployments freeze that draft store at build time, so acceptance rates decay as each user's tool-calling habits change.

SPECMEM writes every verified tool call back into a bounded per-user least-recently-used store during live operation.

The memory becomes a continuously updated cache of that user's recurring patterns.

A side-effect gate runs a deterministic check before any irreversible action is allowed to be drafted.

That removes the failure mode where a high-confidence but dangerous call slips through on a stale draft.

Because the store is scoped per user, cross-user leakage disappears without extra isolation layers.

On multi-session, multi-user query streams served by three open-weight models, it holds a twenty-seven percent gap in mean accepted tokens against a frozen store that steadily loses acceptance.

Wall-clock speedup reaches one point seven four times, because fewer tokens are decoded autoregressively once the store stabilizes.

The tradeoff is extra memory per active user and the need to persist the store across sessions.

Forgetting to gate irreversible actions turns the optimization into a correctness regression.

Teams should adopt live memory when they already log tool calls and can afford per-user state, and otherwise a static high-quality seed store plus periodic refresh remains simpler.
