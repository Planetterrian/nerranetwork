OK, let's pop the hood on the new prompt caching implementation.

The G P T 5.6 system lets developers insert explicit cache breakpoints and guarantees a thirty-minute minimum lifetime.

It charges one point two five times the normal input rate on the initial write while subsequent reads receive the familiar ninety percent discount.

The thirty-minute floor prevents indefinite cache bloat while still covering most multi-turn sessions.

In practice this favors workloads that re-use the same long context within a half-hour window, such as coding agents or document analysis.

The main gotcha teams encounter is forgetting to place breakpoints at stable context boundaries, which either causes misses or loses the discount through overly granular caching.

Use explicit breakpoints when your agent re-processes the same system prompt or retrieved documents multiple times in quick succession.

Skip them for single-shot or highly variable prompts where the write penalty outweighs any read benefit.
