Okay, let's pop the hood on the new prompt caching implementation.
The GPT 5.6 system lets developers insert explicit cache breakpoints and guarantees a 30-minute minimum lifetime.
It charges 1.25 times the normal input rate on the initial right, while subsequent reads receive the familiar 90% discount.
The 30-minute floor prevents indefinite cache bloat while still covering most multi-turn sessions.
In practice, this favors workloads that reuse the same long context within a half-hour window, such as coding agents or document analysis.
The main gotcha teams encounter is forgetting to place breakpoints at stable context boundaries, which either causes misses or loses the discount through overly granular caching.
Use explicit breakpoints when your agent reprocesses the same system prompt or retrieve documents multiple times in quick succession.
Skip them for single shot or highly variable prompts where the right penalty outweighs any read benefit.
