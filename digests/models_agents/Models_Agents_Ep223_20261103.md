# Models & Agents
> **An LLM edited just 0.016 percent of a small model's weights to raise its math benchmark score from 7.9 to 48.1 percent.**

**What You Need to Know:** MIT CSAIL researchers demonstrated that frontier LLMs can directly read and rewrite the weights of smaller neural networks using natural language instructions, without gradient descent or retraining. GPT-6 Astra identified game policies from raw weights alone, wrote new networks from scratch, and fixed reasoning loops in Qwen3.5-0.8B to lift MATH-500 and GSM8K scores dramatically while also improving instruction following. Builders should watch how this "weight-space programming" approach evolves for model editing and interpretability tasks.
---
### Top Story
MIT researchers showed that a general-purpose LLM can examine a neural network's weights as text, identify what the network was trained to do, and modify those weights directly with natural-language instructions. In one experiment the team trained four identical-architecture networks on Breakout, Pong, Pac-Man and Freeway; GPT-6 Astra received only the 17,253 raw weights of each network and correctly named every game. A second set of tests used the same model to repair Qwen3.5-0.8B by changing 0.016 percent of its weights, raising MATH-500 from 7.9 percent to 48.1 percent, GSM8K from 13.8 percent to 67.1 percent, and IFEval from 21 percent to 62.3 percent. The changes primarily suppressed repetitive reasoning loops rather than adding new mathematical ability. The work, published November 2 by Rikiya Takehi, Jayden Teoh, Alex Zhang and Omar Khattab at MIT CSAIL, is still preliminary and has not been peer-reviewed. ### Under the Hood: Continuous Batching in LLM Inference Servers
Continuous batching keeps GPU utilization high by adding new requests to an in-flight batch as soon as earlier sequences finish, rather than waiting for an entire static batch to complete. The key engineering move is dynamic KV-cache management: each request maintains its own key-value cache slice that can be appended to on the fly while the attention mask is recomputed for the current active set. This removes the classic "all requests must finish together" constraint and replaces it with a scheduler that decides, at every step, which sequences to run and which to pause. The throughput gain is largest when request lengths vary widely; a fleet seeing a mix of short chat turns and long document summaries can reach 2–4× higher tokens per second than static batching at the same model size. The tradeoff appears in added scheduling overhead and more complex memory fragmentation, because the KV cache is no longer a single contiguous block. Most production servers therefore combine continuous batching with paged attention or block-wise cache allocation to keep fragmentation under control. Use continuous batching when average request length is short relative to the model context and arrival rate is high; fall back to static or semi-static batching when requests are uniformly long or when strict per-request latency SLAs dominate. The practical gotcha is that cache-eviction policies must be tuned per workload; an aggressive eviction rule that works for chat can silently drop long-context retrieval sessions.
