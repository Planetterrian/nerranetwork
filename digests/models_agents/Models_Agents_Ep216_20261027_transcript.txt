Soft prompt compression paid a quadratic transformer tax on every extra token, so it is time
to pop the hood on the Boa compressor.
Boa replaces that transformer backbone with a Mamba state space model that encodes arbitrary
length context in a single linear time pass.
That pass produces a representation which conditions a frozen target LLM.
The state space model is trained by distillation, so its compressed representation produces
the same next token logits as the target LLM ingesting the full context.
Because the compressor runs online on every query instead of once offline, it removes the
latency overhead that previously confined soft prompt methods to repeated query settings.
At identical compression ratios, the approach matches or exceeds prior offline transformer
based baselines.
Compression time drops by roughly an order of magnitude.
It continues to scale to 16 times compression and longer contexts without the quadratic cost
that grows with transformer based compressors, and without adding per query overhead.
The practical limit appears when the target LLM's own context window becomes the bottleneck
rather than the compressor itself.
Teams facing repeated long-context queries should test BoA first.
Teams that compress once and reuse across many queries can still prefer the older offline
methods.
