### Top Story
Liquid AI released d1.2 and d1.2-ultra, omnimodal decision models that ingest text, images and audio and emit calibrated probabilities without producing any output tokens. The d1.2-ultra variant scores 75 on the Artificial Analysis Decision Index v2.1. These models target decision tasks where a probability distribution is more useful than generated text. Builders working on risk scoring, routing or verification pipelines can now call a single endpoint that returns well-calibrated numbers across modalities. The models read three distinct input types in one forward pass and return only numeric outputs, eliminating token generation overhead. Watch for follow-on releases that add support for longer context windows or additional sensor inputs. The release positions Liquid AI in the growing space of specialized decision models that prioritize calibrated outputs over fluent text. ### Model Updates
**Sarvam Launches Sarvam Token Factory: Bringing India-Hosted Inference to 8 Open Models — MarkTechPost**
Sarvam Token Factory now serves Sarvam 105B, GLM 5.3, DeepSeek V4.1 Flash, Kimi K3.1 Pro and Gemma 4 31B from GPU clusters located in India through a single OpenAI-compatible API. The platform is open to everyone and routes requests to eight distinct open models hosted on domestic infrastructure. Developers gain an alternative endpoint that avoids routing through US or European providers while maintaining the same request format used with OpenAI clients. The service aggregates multiple model families under one set of credentials and billing. Latency and cost comparisons become straightforward because every model shares the identical API surface. Early users can test inference for both dense and mixture-of-experts architectures without changing client code. Source: [marktechpost.com](https://www.marktechpost.com/2026/11/17/sarvam-token-factory-india-inference-platform/)

### Agent & Tool Developments
**Sandbox credential isolation benefits — Simon Willison (AI builder) (X)**
The design keeps the agent's own credentials outside the sandbox, allows complete network disablement inside the sandbox while the agent still reaches its model, and prevents untrusted code from touching agent configs or logs. By separating identity material from the execution environment, operators reduce the blast radius of any compromise inside the sandbox. The same boundary also stops sandboxed processes from reading or overwriting configuration files and execution logs that remain on the host. Full network isolation becomes practical because the model endpoint is reached through a host-side proxy rather than direct outbound sockets. This pattern supports running thousands of sandboxes on a single host without credential sprawl across every container image. Source: [x.com](https://x.com/simonw/status/2122537630080667981)

**External sandbox prototypes GitHub repo — Simon Willison (AI builder)**
Willison and Prime Radiant published the index repository for the external sandbox prototypes at https://github.com/prime-radiant-inc/external-sandbox. The repository serves as the central index for multiple sandbox server implementations developed in collaboration with the AI research lab behind Superpowers. Each implementation demonstrates the credential isolation and proxy patterns described in the accompanying posts. Builders can clone the repo to inspect working examples of network-restricted, credential-free agent runtimes. The project focuses on practical deployment rather than new research abstractions. Source: [github.com](https://github.com/prime-radiant-inc/external-sandbox)
