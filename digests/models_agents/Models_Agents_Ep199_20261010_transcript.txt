Pop the hood on expert prefetching in mixture of experts' inference on consumer hardware.
MoE models keep most parameters off the GPU until needed, yet loading experts from SSD during
generation creates a hard latency wall.
The key mechanism is a small pre-fetch buffer that predicts the next layer's active experts
from the current Tokens router low jits and issues asynchronous reads while the current
layer computes.
This adds roughly 200 milliseconds of pipeline latency per request, but cuts peak VRAM
usage by more than half compared with keeping every expert resident.
On a 68GB model running on a 16GB card, the pre-fetch version sustains 20 tokens per second
once the working set warms, versus one to two tokens per second with plain M-map.
The quality tradeoff is zero because the pre-fetch is bid exact.
The only cost is the extra SSD bandwidth during cold starts.
Teams should enable pre-fetch when VRAM is under 30% of model size
and disable it when the entire expert set already fits,
because the added latency then has no offsetting memory win.
