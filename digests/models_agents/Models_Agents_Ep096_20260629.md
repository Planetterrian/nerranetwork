### Model Updates
**Yuvion LLM: An Adversarially-Aware Large Language Model for Content And AI Safety: cs.CL updates on arXiv.org**
Yuvion LLM is a new model family trained with adversarially aware data construction, knowledge-enhanced pretraining, and policy-grounded safety post-training that includes risk-aware supervised fine-tuning plus reinforcement learning for tool use. The 8B variant reportedly outperforms several larger baselines including GPT-5.4 and Qwen3-MAX on multiple safety benchmarks while maintaining competitive general capability. It ships with the Yuvion LLM RiskEval suite spanning 93 benchmarks focused on adversarial robustness and real-world safety scenarios. Builders working on agentic systems that must resist jailbreaks should test the 8B checkpoint this week against their current safety stack. Source: [arxiv.org](https://arxiv.org/abs/2606.27632)

**The Context-Ready Transformer: cs.CL updates on arXiv.org**
The context-ready transformer adds a lightweight correction network that pre-contextualizes each token before it enters the main D-layer transformer block, turning the architecture into a recurrent model at inference time. A D=5 configuration beats a standard 12-layer transformer while running 1.7x faster on an A100; a single-layer version with K=10 unrolling matches a 6-layer baseline at 2.6x speedup. The approach works by caching a summary of prior context and combining it with the current token embedding via a zero-initialized correction FFN during fine-tuning. Teams running long-context inference on limited hardware should experiment with converting existing checkpoints using the described adaptation path. Source: [arxiv.org](https://arxiv.org/abs/2606.27538)

**EntMTP: Accelerating LLM Inference with Entropy Guided Multi Token Prediction: cs.CL updates on arXiv.org**
EntMTP introduces a training-free scheduler that switches between different tree-based attention topologies for multi-token prediction based on a running estimate of local generation entropy. It delivers a 1.15x average speedup over Hydra and up to 1.36x over Medusa across Humaneval, ShareGPT, GSM8k, and Litbench while preserving output quality. The method avoids the fixed speculation depth of prior MTP approaches by matching draft length to context predictability. Developers using speculative decoding today can drop the scheduler into existing Hydra or Medusa setups with minimal changes. Source: [arxiv.org](https://arxiv.org/abs/2606.27550)

### Practical & Community
**RAGless: Q-Q retrieval with score aggregation for closed-domain FAQ [P]: r/MachineLearning**
RAGless replaces standard document retrieval with question-to-question matching: an LLM generates 3–5 variants per answer at ingestion, each gets its own embedding, and query-time scores are aggregated by answer ID using dual thresholds (0.70 aggregated, 0.82 single-hit fallback). The GitHub repo at github.com/EmilResearch/RAGless provides the implementation under an open license. It targets closed-domain FAQ systems where the answer space is finite and eliminates the generation step entirely. Teams maintaining internal knowledge bases should compare precision against their current RAG pipeline on a held-out set of questions. Source: [reddit.com](https://www.reddit.com/r/MachineLearning/comments/1uilov7/ragless_qq_retrieval_with_score_aggregation_for/)

**Supersede: Diagnosing and Training the Memory-Update Gap in LLM Agents: cs.CL updates on arXiv.org**
Supersede introduces an RL environment that rewards agents for using the current value of a fact and penalizes stale information, directly targeting the memory-update gap observed on LongMemEval. Fine-tuning Qwen2.5-3B with GRPO on this environment raised held-out supersession accuracy from 9.0% to 16.7%. The benchmark and training stack are released publicly. Agent developers dealing with multi-session conversations where facts change should add the Supersede verifier to their evaluation harness. Source: [arxiv.org](https://arxiv.org/abs/2606.27472)

### Under the Hood: Entropy-Guided Multi-Token Prediction
Everyone talks about multi-token prediction as a simple way to speed up generation. In practice, EntMTP shows it is a dynamic scheduling problem where speculation depth must track local entropy. Low-entropy regions support deeper drafts with high acceptance rates; high-entropy regions require shallower trees to avoid wasted verification compute. The scheduler maintains a running entropy estimate and switches among a small set of precomputed Pareto-optimal trees, adding negligible overhead while lifting average accepted tokens per step. On the tested benchmarks the approach yields 1.15–1.36x speedups without quality loss because it avoids the fixed-depth penalty that hurts earlier static MTP methods. The key engineering decision is keeping the tree library small and task-specific rather than attempting online tree search. Use entropy-guided scheduling when your workload contains mixed predictability (code mixed with open text, or structured JSON with occasional free-form fields); fall back to standard speculative decoding only if your generation distribution is uniformly high-entropy.
