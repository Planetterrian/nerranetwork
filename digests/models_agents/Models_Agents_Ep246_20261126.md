# Models & Agents
> **Claude Opus 5.5 turned 31 real US government datasets into a playable Civilization-style map with 25 km hexes, 19 lenses, and 524 metro views.**

**What You Need to Know:** Andrej Karpathy used the Claude Code desktop app and Opus 5.5 to reconcile Census, BEA, BLS, EIA, NOAA, USGS and 25 other public sources into one consistent 25 km hex grid, converting GDP into gold yield and real industries into city districts. The result includes nine advisors, an Explorer tool that turns any county column into tables and scatter plots, and a City View for every metro. Builders can now browse the live demo to see how frontier models handle large-scale public data reconciliation without custom training.
---
### Top Story
Andrej Karpathy asked Claude Opus 5.5 to populate a Civilization-style game map with real US public data. Opus downloaded and parsed 31 sources including Census, BEA, BLS, EIA, NOAA, USGS, DoD, NPS, FAA, FEMA and CDC, then reconciled elevation, land cover, GDP, jobs, power plants, mines, ports, airports, bases, parks, universities, freight flows and disasters onto a single 25 km hex grid. The model mapped real metrics into game terms—GDP became gold yield, San Jose received a Campus district, Detroit became Motor City—and assigned citizen specializations based on actual workforce data such as one in four San Jose workers being engineers, coders or scientists. It added 19 lenses covering income, degrees, faith and disasters, a City View for 524 metros, nine advisors and an Explorer that converts any column across 3,100+ counties into tables and scatter plots linked to the map. The project ran for 7 hours and 45 minutes, produced 45K lines of code, and is now live for anyone to browse and extend. Karpathy noted that Claude decided to skip a few states and territories. The map is built using the Claude Code desktop app with Opus 5.5 on medium reasoning and ultracode mode enabled. A trailer video was also generated by the model. Source: [t.co](https://t.co/QMhmafXMj5)

**Building on Nemotron 3.5 Parse: Open Data, Fine-Tuning, and Faster Inference: Hugging Face Blog**
NVIDIA released synthetic training datasets, a fine-tuning recipe and a DFlash2 speculator for faster inference on top of Nemotron 3.5 Parse, the compact document model that turns page images into structured data for RAG and agents. The team open-sourced three datasets: Synthetic Charts V1 with 9.98M examples, Synthetic Tables V1 with 1M examples, and OCR Synthetic Multilingual v2 with 7.9M examples, all used to improve chart and table extraction through supervised fine-tuning followed by reinforcement learning. Parse extracts content from document pages into reading order, assigns classes such as headings, paragraphs, tables and charts, and returns bounding boxes. The latest version extends ability to read charts and tables in difficult cases, including bar charts without marked numeric values where the model infers values from axes and bar heights. Tables benefit from structure preservation that avoids shifts in rows or columns that would alter meaning. Training began with supervised fine-tuning on document understanding then moved to reinforcement learning for accuracy, consistency and reliable completion. The DFlash2 speculator targets faster inference while the synthetic data approach renders chart and table variations with known ground truth so the model learns to reverse the process. Source: [huggingface.co](https://huggingface.co/blog/nvidia/building-on-nemotron-35-parse-open-data-fine-tunin)

### Under the Hood: MGMem Long-Horizon Agent Memory
MGMem replaces the usual generative-LLM summarization step in long-horizon agent memory with a deterministic discriminative-parser pipeline that builds an incidence graph from recurring mentions across sessions. The system resolves question mentions through a subject-conditioned three-stage resolver and returns the original raw dialogue episodes instead of synthesized text, eliminating thousands of generative calls per build, non-determinism, and loss of provenance. On English multi-session dialogue QA it outperforms matched-protocol baselines on LoCoMo without any generative indexing and remains competitive on the full LongMemEval-S benchmark while leading or tying on single-session retrieval tasks. The incidence graph organizes recurring entity mentions across multiple sessions so that later queries can retrieve exact source turns rather than paraphrased summaries. The three-stage resolver conditions on the subject of the current question to disambiguate which past mentions are relevant, avoiding the need for an LLM to rewrite history at indexing time. Because raw episodes are returned, any downstream reader sees the precise original utterances and can verify context directly. The design trades the flexibility of learned abstractive summaries for guaranteed reproducibility and direct provenance, which becomes critical when agents must cite exact past interactions or when repeated generative calls would exceed budget limits. The framework was evaluated on both the LoCoMo multi-session QA task and the broader LongMemEval-S suite, showing particular strength on single-session retrieval subtasks where local context dominates. When an agent workflow requires auditability or when memory indexing must avoid stochastic LLM calls, MGMem provides a drop-in deterministic alternative; generative summarization remains preferable only when heavy abstraction across thousands of turns is the primary goal and exact wording is secondary. Source: [arxiv.org](https://arxiv.org/abs/2611.33174)
