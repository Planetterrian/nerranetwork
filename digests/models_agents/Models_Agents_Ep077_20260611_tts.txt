OK, let's pop the hood on agent state persistence.

Most people picture agent memory as a simple append-only log.

In practice the design choices around durability, query speed, and consistency turn expensive fast.

Long-running agents need both short-term scratch space and durable cross-session facts.

Mixing the two either drops context or drives storage costs through the roof.

A production stack therefore keeps an in-memory working set for the current run and a separate indexed store that mixes vector and relational data for facts that survive restarts.

Adding the second layer adds thirty to eighty milliseconds per tool call for serialization and indexing.

It also avoids replaying every prior step on every restart.

The tradeoff shows up once agents pass roughly two hundred tool calls in one session.

After that point the cost of keeping everything in context exceeds the cost of selective persistence.

Teams should start with a simple key-value layer and add vector search only after they see repeated lookups of the same facts across sessions.

Most early agent workloads never hit that threshold.
