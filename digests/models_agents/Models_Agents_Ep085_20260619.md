### Model Updates
**DeepSeek-V4: Towards Highly Efficient Million-Token Context Intelligence: arXiv**
DeepSeek previewed the V4 series with two MoE models: V4-Pro (1.6T total, 49B active) and V4-Flash (284B total, 13B active), both supporting 1M token context. The models use hybrid Compressed Sparse Attention plus Heavily Compressed Attention, Manifold-Constrained Hyper-Connections, and the Muon optimizer after pre-training on over 32T tokens. V4-Pro-Max reportedly sets a new open-model reasoning bar while cutting inference FLOPs to 27% and KV cache to 10% of the prior version at million-token lengths. Checkpoints are already on Hugging Face. Builders running long-horizon agents should test the 1M context mode this week to see where the efficiency gains actually appear in practice. Source: [arxiv.org](https://arxiv.org/abs/2606.19348)

**Liquid AI Introduces LFM2.5-Embedding-350M and LFM2.5-ColBERT-350M: MarkTechPost**
Liquid AI released two 350M parameter retriever models: a dense bi-encoder and a ColBERT late-interaction variant for fast multilingual search. The pair targets edge deployment across 11 languages with a focus on low-latency retrieval. The models combine dense and late-interaction approaches to balance speed and accuracy on resource-constrained hardware. Developers building on-device RAG or search features now have a compact, multilingual option that avoids larger cloud models. ### Under the Hood: Million-Token Context in MoE Models
Everyone talks about “million-token context” as if it is simply a bigger KV cache. In practice, it requires coordinated changes across attention, residual connections, and optimizer to keep both memory and compute manageable. DeepSeek-V4’s hybrid CSA + HCA approach compresses the attention computation so that a 1M-token forward pass uses only 27% of the FLOPs and 10% of the KV cache of the prior version. The Manifold-Constrained Hyper-Connections further stabilize training at this scale by replacing standard residuals with learned manifold projections. At inference time the savings only appear once context exceeds roughly 128k tokens; below that the overhead of the compressed paths can actually slow things down. Teams should therefore profile both short and long contexts before committing to these architectures. The practical decision rule is simple: if your typical agent session stays under 100k tokens, the new mechanisms add complexity with little payoff; once you routinely exceed that threshold, the efficiency gains become decisive.
