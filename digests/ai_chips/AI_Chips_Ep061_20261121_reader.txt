Microsoft turned on a path that lets one Windows 11 PC read memory in another over USB4, and that link is worth taking apart. TechPowerUp's account is a latency test. Remote direct memory access skips the usual copy through the operating system, so a job can sit on several daisy-chained machines and touch the next machine's memory with that CPU mostly out of the way.

USB4 is the cable, up to 80 gigabits per second. Ethernet can already ride the same cable, and a UDP packet on that Ethernet path is the thing Microsoft measured against. UDP still wraps the message, queues it, and copies it before the far memory is involved. The bet is that the software stack, not the wire, was the wait. Two PCs, latency versus message size.

RDMA over USB4 came back in 28 to 50 microseconds. Ethernet over USB4 with UDP came back in 116 to 194 microseconds. Fast end, 28 against 116. Slow end, 50 against 194. The outlet calls that roughly four times quicker. A picture of DGX Spark machines tied with Ethernet is not this test, so it does not add a number.

A short message finishes before an 80-gigabit pipe is full, which is why the 28-to-50-microsecond access is what you feel and why the UDP band is a stack tax. Stretch the message and the bytes have to occupy that pipe, while the protocol gap stays inside the band already measured.

Daisy-chained PCs stop being the right fabric when the job is limited by how many bytes that 80-gigabit pipe can move, not by the memory access — a wider network then finishes the step, and the fourfold latency win no longer decides it.
