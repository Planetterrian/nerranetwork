### The Teardown: CXL Memory Pooling in the MX1
Take it apart and the MX1 places RISC-V cores directly alongside DDR5 and SSD arrays connected through CXL links. This layout lets the cores perform local reductions and filtering before any data crosses the host PCIe bus. Each CXL-attached module therefore cuts the volume of traffic that would otherwise traverse the narrower host interface. The design also lets the SSDs serve as a slower but larger tier that the RISC-V cores can address without first staging everything in host DRAM. When the working set fits inside the pooled DDR5, latency stays comparable to local memory; once the set spills to the SSD tier, bandwidth drops but capacity scales without adding more host sockets. The tradeoff flips when the ratio of compute to data movement exceeds the CXL link rate, at which point the added cores no longer offset the extra hop.
