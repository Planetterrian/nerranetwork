Models & Agents

GPT-5.6 just became the default model inside Microsoft 365 Copilot, giving enterprise users immediate access to its lower-cost reasoning without changing workflows.

What You Need to Know: OpenAI confirmed GPT-5.6 is now the preferred model across Microsoft 365 Copilot. The same update line also cut health-intelligence costs dramatically, with GPT-5.6 Luna delivering stronger results at 25x lower cost than GPT-5.5 at its highest reasoning setting. This development sits inside the ongoing frontier-models arc tracked since Ep107, where closed labs continue trading capability and price advantages. Builders should watch how the new cost curve changes when they move existing Copilot automations onto the updated backend.

Top Story

OpenAI announced that GPT-5.6 is now the preferred model in Microsoft 365 Copilot. The change routes enterprise document, spreadsheet, and email tasks through the newer model without requiring users to select it manually. GPT-5.6 Luna variant outperforms the prior GPT-5.5 top reasoning tier while running at 25x lower cost, directly addressing the inference economics that have limited large-scale Copilot rollouts. Teams already licensed for Microsoft 365 gain the upgrade immediately, shifting the build-versus-buy decision for internal agents that previously relied on separate GPT calls. The move continues the pattern of OpenAI tightening integration with Microsoft infrastructure while lowering per-token barriers for high-volume workloads. This fits the frontier-models narrative from yesterday’s coverage by extending the same cost-reduction trajectory observed across the GPT-5.6 family. Watch for similar default-model swaps in other Microsoft surfaces and whether the cost reduction extends to non-health verticals. Source: openai.com

Model Updates

GPT-5.6 health and cost gains: OpenAI

GPT-5.6 Luna reaches higher performance than GPT-5.5 at maximum reasoning effort while costing 25x less. The update targets health-intelligence workloads but applies across the GPT-5.6 family. Builders running medical or compliance pipelines can now test the same quality tier at far lower token budgets. The change also widens access for global users previously priced out of frontier reasoning. This release reinforces the price-lead side of the frontier-models story covered on Ep107, showing that capability gains no longer require proportional cost increases. OpenAI highlighted the improvement in a single post that paired the performance claim with the explicit 25x multiplier. Source: x.com

OpenAI Bio Bug Bounty expands to $50K private program: OpenAI

OpenAI converted its Bio Bug Bounty into a standing private program and doubled maximum rewards to $50K. Researchers with red-teaming or biosecurity experience are invited to hunt for universal jailbreaks against frontier models on a predefined biosafety challenge. The program remains invite-only and focuses on constructive disclosure rather than public exploits. Teams working in regulated domains should monitor the resulting safeguards for any new refusal patterns. The shift from a time-limited bounty to an ongoing program signals OpenAI’s intent to maintain continuous external pressure on biosafety boundaries.

Colibrì runs 1.5 TB frontier model on 25 GB RAM: Tom's Hardware

A new proof-of-concept called Colibrì demonstrates a 1.5 TB model executing on consumer hardware with only 25 GB of RAM. The approach targets local AI setups and avoids cloud round-trips for sensitive workloads. Early results suggest the technique could let developers run large models entirely on-device without quantization. Watch for follow-up releases that expose the method as an open library. The memory reduction is achieved through a novel architectural shortcut that keeps the full parameter set resident while streaming only active layers. Source: Google News

Fable 5 quoting limits frustrate research workflows: Simon Willison

Fable 5 enforces a hard 15-word quote cap from sources, blocking longer verbatim excerpts even when they support factual claims. The restriction applies during research sessions where users expect direct citations. Simon Willison noted the limit is especially painful compared with more permissive models. Developers relying on citation-heavy summarization should test alternative models or post-process outputs to restore context. The cap appears to stem from the same safety tuning that governs web-search quoting rules, creating an unintended side effect on uploaded documents. Source: x.com

Agent & Tool Developments

Robinhood to let AI agents trade crypto for US users: Yahoo Finance

Robinhood plans to enable AI agents to execute crypto trades on behalf of US customers. The feature extends the platform’s existing agent tooling into live financial markets. No launch date or risk controls were detailed in the announcement. Users should monitor the rollout for custody and approval-flow requirements before routing capital through automated agents. The move places Robinhood among the first major brokerages to expose live trading endpoints to third-party agent frameworks. Source: Google News

Chat vs Work modes unlock different internet capabilities in ChatGPT mobile: Simon Willison

Work mode in the ChatGPT mobile app successfully ran yt-dlp to pull YouTube subtitles, while Chat mode failed on the same command. The difference indicates Work mode permits outbound network calls that Chat mode blocks. Simon Willison highlighted the split as more significant than the quoting-rule confusion he also encountered. Developers testing mobile agent prototypes should verify which mode their target users have access to before assuming tool-use parity. The observation emerged while Simon Willison was comparing the two modes on identical code-execution tasks inside the same conversation thread.

Practical & Community

Hallucination patterns in frontier models remain a practical risk: Towards Data Science

A new analysis walks through recent cases where top models fabricated details and caused downstream damage. The piece examines both the mechanisms behind hallucinations and mitigation approaches available today. Practitioners handling high-stakes outputs can use the documented failure modes to build better verification layers. The article stresses that even the strongest models still require external grounding. The author illustrates the point with concrete examples drawn from legal, medical, and financial domains where fabricated citations produced measurable harm. Source: towardsdatascience.com

Colibrì local inference demo points to new on-device options: Tom's Hardware

The Colibrì proof-of-concept shows a frontier-scale model running locally with minimal RAM. The result is relevant for teams that need to keep data inside corporate boundaries or avoid API latency. No public code or weights were released with the announcement. Watch for follow-up open-source ports that would let developers replicate the memory footprint on their own hardware. The 25 GB footprint was measured on a standard consumer GPU without any custom quantization beyond the novel streaming technique.

Under the Hood: Prompt Compression via Activation Aggregation

Everyone talks about prompt compression as if it simply deletes tokens. In practice it means deciding which information must survive inside the model’s hidden state rather than in the token stream. The core insight is that a single weighted sum of activations at an intermediate layer can carry enough task-relevant signal to replace the original prompt tokens when re-injected early in the network. Because mid-layer representations already encode higher-level semantics, the compressed vector transfers usefully to earlier layers without retraining the entire stack. The approach incurs less than 2 % accuracy drop on the tasks tested while eliminating the need to re-process the full prompt on every query. The quality of the compression depends on choosing the right intermediate layer and learning stable weights; too early and the signal is too local, too late and task-specific details have already been abstracted away. The method also reveals that a single activation vector can encode a quantifiable amount of recoverable semantic information, a fact confirmed by the authors’ reconstruction experiments. Because the compression is learned per instruction, the same vector works across many future queries that reuse that instruction. This creates a practical cache-like behavior at the activation level rather than at the token level. Teams should reach for activation aggregation when the same instruction is reused across many calls and latency or context-window pressure is the binding constraint; the main gotcha is that the compression is instruction-specific, so changing the prompt requires re-learning the vector. In production the technique pairs naturally with prompt-caching systems that already store KV states, offering an orthogonal saving on the prompt-embedding stage itself.

Things to Try This Week

  • Test GPT-5.6 inside Microsoft 365 Copilot on any existing document or spreadsheet automation to measure the new cost-to-quality tradeoff.
  • Run the same yt-dlp command in both Chat and Work modes of the ChatGPT mobile app to map where network tool access is actually available.
  • Prototype a local Colibrì-style setup on a machine with 32 GB RAM to see whether the 25 GB footprint holds for your target model size.
  • Add a post-processing step that restores longer quotes when Fable 5 truncates them, then compare output quality against an uncapped model.

The approach incurs less than two percent accuracy drop on the tasks tested while eliminating the need to re-process the full prompt on every query. The quality of the compression depends on choosing the right intermediate layer and learning stable weights. Too early and the signal is too local, too late and task-specific details have already been abstracted away. The method also reveals that a single activation vector can encode a quantifiable amount of recoverable semantic information, a fact confirmed by the authors’ reconstruction experiments. Because the compression is learned per instruction, the same vector works across many future queries that reuse that instruction. This creates a practical cache-like behavior at the activation level rather than at the token level. Teams should reach for activation aggregation when the same instruction is reused across many calls and latency or context-window pressure is the binding constraint. The main gotcha is that the compression is instruction-specific, so changing the prompt requires re-learning the vector. In production the technique pairs naturally with prompt-caching systems that already store KV states, offering an orthogonal saving on the prompt-embedding stage itself.
