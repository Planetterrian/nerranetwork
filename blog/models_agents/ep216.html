OpenAI’s GPT-6.1 Terra delivers faster computer-use agents at half the prior token price.

By Patrick October 27, 2026 Ep 216 8 min read Listen to podcast Watch on YouTube
Listen in
Contents

What You Need to Know: OpenAI began rolling out GPT-6.1 Terra to ChatGPT Work, Codex, and the API as gpt-6.1-terra, with 50% lower standard API prices than GPT-5.6 Terra and strong results on agent benchmarks. The model handles screen understanding, cross-app actions, and natural writing while finishing tasks over 3× faster than GPT-6 Astra on average. Builders should test it first for agentic workflows where cost and speed matter more than maximum capability.

Top Story

OpenAI released GPT-6.1 Terra, a new model optimized for fast, capable computer use at lower cost. It understands screen content, performs actions across applications, and writes naturally while matching GPT-6 Astra performance on Agents’ Last Exam at one-tenth the price per token. The model finishes tasks over three times faster on average than both Astra and GPT-6.1 Sol. In ChatGPT Work and Codex the usage allowance stretches further than with GPT-5.6 Terra. Developers can access it immediately through the API or ChatGPT interfaces for agent-style work. Watch for continued price and speed improvements across the GPT-6.1 family as OpenAI pushes the cost-intelligence frontier. Source: openai.com

Model Updates

OpenESM: Energy-Steered Models Are Scalable Foundation Learners: arXiv NLP

OpenESM integrates energy steering and token generation in one architecture that first optimizes a latent state over an energy landscape before using the refined state for generation. The models were pre-trained on three large-scale corpora and evaluated on 26 downstream tasks, where they show promising scaling behavior and outperform GPTs on most tasks. The team fully releases model weights and training infrastructure on GitHub and Hugging Face. Source: arxiv.org

Linear-Time Context Compression with State-Space Encoding: arXiv NLP

The Boa Compressor uses a Mamba state-space model to encode arbitrary-length context in a single linear-time pass and produces a representation that conditions a frozen target LLM. At equal compression ratios it matches or exceeds existing offline Transformer-based baselines while running an order of magnitude faster. The method scales to 16× compression and longer contexts without adding per-query overhead. Source: arxiv.org

Conceptizer: Next-Token Prediction Is Not All You Need: arXiv NLP

Conceptizer adds a fixed ~9K-concept vocabulary of contextual synonyms to next-token training so the model receives a reward for meaning rather than only the exact next token. Applied to 1B–8B models across three families, it achieves the lowest held-out perplexity at concept-target positions and the highest probability on contextual synonyms. Downstream gains appear on knowledge and sentiment tasks while commonsense performance stays comparable. Source: arxiv.org

Merge-Based Vocabulary Extension Stalls at the Pre-Tokenizer: An English-Preserving Repair for Nepali, Tested in Continued Pretraining: arXiv NLP

A small regex edit to the pre-tokenizer keeps every token ID of text without combining marks or Devanagari characters and, with 32,000 new merges, reduces Nepali token count to 1.01 times English. The repair cuts Nepali tokens by about 54% versus standard vocabulary extension on Llama-3 and Qwen3. Continued pretraining experiments on Llama-3.2-1B and Qwen3-0.6B show the original tokenizer still wins on held-out Nepali bits per byte under every tested recipe. Source: arxiv.org

AdaptTok-Indic: Script-Aware Adaptive Tokenization for Indic Languages: arXiv NLP

AdaptTok-Indic combines Unicode-normalized preprocessing, explicit Indic conjunct handling, script-aware routing, and learned byte-level boundary prediction. On Bengali and Hindi it records mean fertility of 1.432 and 1.388 respectively, well below SentencePiece BPE. Downstream scores average 57.69 on evaluated Indic settings versus 50.82 for the SentencePiece baseline. Source: arxiv.org

Agent & Tool Developments

Recursive Semantic Divergence for LLM Agent Consistency: arXiv NLP

Recursive Semantic Divergence measures expected cumulative semantic disagreement between independent rollouts of the same agent from the same state using natural language inference. When used as a reward signal it reduces task-progress variation from 132% to 91% on tau2-bench and from 90% to 44% on toolsandbox while improving performance across benchmarks and scales. The metric requires no ground-truth labels and estimates future divergence from the current state. Source: arxiv.org

SLICE-Mem: Salience-Gated Lightweight Information Curation for Efficient LLM Agent Memory: arXiv NLP

SLICE-Mem uses a compact classifier for salience-guided admission and a semantic-dependency extractor that converts turns into concise memory entries without generative LLM calls. On Memora Weekly and LongMemEval-S with Qwen3-30B backbones it matches the generative baseline MemOS while cutting total LLM token consumption by 92.4% and 99.5% respectively. Cross-entry reconciliation is deferred to an offline stage. Source: arxiv.org

FlexA-Mem: Budget-Adaptive Agentic Memory for LLM Agents: arXiv NLP

FlexA-Mem writes each unit of history once into an immutable store and renders a fresh compact timeline plus detail for every call using a fixed rule that fits remaining budget without an LLM call. On AppWorld at 4k context it outperforms the second-best method by 11.5% and on 147 unused tasks it beats A-Mem with summary by 12.2%. The timeline carries completion while recovery mainly saves steps. Source: arxiv.org

TraceQuery: learning what to recompute from full-denoising trajectory in diffusion language models: arXiv NLP

TraceQuery predicts a small set of near-future trajectory-relevant positions from full-denoising trajectories and queries only those candidates. It delivers the strongest quality-computation trade-off among cache-based approaches for diffusion LLMs while generalizing across tasks, model variants, and families. Code is released on GitHub. Source: arxiv.org

Practical & Community

Entity-Aware Evaluation of OCR Systems for Historical Document Transcription: arXiv NLP

The work introduces entity-level analysis of OCR errors on a 175-document benchmark from the Berrutti Archive containing 5,209 manually annotated entity mentions. Qwen 3.6 achieves the highest entity coverage across tolerances while several lower exact-match systems recover substantially when small character errors are tolerated. The benchmark and annotations will be released upon acceptance. Source: arxiv.org

Whispering Wisely: Smart Subset Selection for ASR Fine-Tuning: arXiv NLP

An embedding-based k-center subset selection method using Whisper’s pretrained encoder selects diverse training subsets for ASR fine-tuning. On Hebrew and Danish the approach often beats random sampling, especially at smaller subset sizes, and k-center subsets capture broader lexical diversity. The method provides a practical way to adapt Whisper to new languages or domains with limited transcribed audio. Source: arxiv.org

A Benchmark for Controllable Speaking-Style Captioning in Audio-Language Models: arXiv NLP

StyleInstructCaps supplies the first standardized benchmark and evaluation framework for instruction-following speaking-style captioning that measures metadata groundedness, hallucination, instruction following, and speaker-style consistency. Across nine state-of-the-art audio-language models, instruction-diverse training substantially improves groundedness and controllability. Source: arxiv.org

EviGround-CT: Sentence-to-Volume Grounding for Verifying LLM-Generated Chest CT Reports: arXiv NLP

EviGround-CT extracts positive finding sentences from LLM-generated CT reports and uses a 3D grounding model to predict evidence masks for each sentence. Sentence-grounded verification raises evidence-supported precision from 0.263 to 0.365 on a held-out 100-case subset while lowering the unsupported positive finding rate from 0.737 to 0.635. Source: arxiv.org

Under the Hood: Linear-Time Context Compression with State-Space Encoding

The Boa Compressor replaces the usual Transformer backbone for soft-prompt compression with a Mamba state-space model that encodes context in one linear-time pass. The SSM is trained by distillation so its compressed representation produces the same next-token logits as the target LLM ingesting the full context. Because the compressor runs online on every query instead of once offline, it removes the latency overhead that previously confined soft-prompt methods to repeated-query settings. At identical compression ratios the approach matches or exceeds prior offline baselines while cutting compression time by roughly an order of magnitude. It continues to scale to 16× ratios and longer contexts without the quadratic cost that grows with Transformer-based compressors. The practical limit appears when the target LLM’s own context window becomes the bottleneck rather than the compressor itself. Teams facing repeated long-context queries should test Boa first; teams that compress once and reuse across many queries can still prefer the older offline methods.

Things to Try This Week

  • Test GPT-6.1 Terra through the OpenAI API or ChatGPT Work for agentic computer-use tasks where speed and token cost dominate.
  • Experiment with the released OpenESM weights on Hugging Face for energy-steered pre-training on your own corpora.
  • Try the Boa Compressor implementation on long-context workloads to measure end-to-end latency versus your current offline compression pipeline.
  • Apply the k-center subset selection method from the Whisper paper when fine-tuning ASR models on Hebrew or Danish data with limited transcribed audio.
  • Evaluate AdaptTok-Indic on Bengali or Hindi text if you need lower token fertility than standard SentencePiece BPE.

OpenESM weights go public, agent-memory papers cut token spend, then Things to Try. OpenAI is rolling GPT-6.1 Terra out to ChatGPT Work, Codex, and the API under the name gpt-6.1-terra. The model understands screen content, performs actions across applications, and writes naturally. It matches GPT-6 Astra on Agents' Last Exam at one-tenth the price per token. Tasks finish over three times faster on average than both Astra and GPT-6.1 Sol. In ChatGPT Work and Codex the usage allowance stretches further than with GPT-5.6 Terra. Developers can access it immediately through the API or ChatGPT interfaces for agent-style work. Energy steering meets token generation in OpenESM, one architecture described in an arXiv paper. The model first optimizes a latent state over an energy landscape, then uses that refined state for generation. Pre-training ran on three large-scale corpora. Evaluation covered twenty-six downstream tasks, where the models outperform GPTs on most of them and show promising scaling behavior. The team fully releases model weights and training infrastructure on GitHub and Hugging Face. Next-token training gets a meaning reward in Conceptizer. Tests on one-billion to eight-billion-parameter models across three families post the lowest held-out perplexity at concept-target positions. The same runs record the highest probability on contextual synonyms. Downstream gains appear on knowledge and sentiment tasks, while commonsense performance stays comparable. Indic language tokenization is the target of AdaptTok-Indic. Unicode-normalized preprocessing and explicit Indic conjunct handling sit alongside script-aware routing. Learned byte-level boundary prediction completes the stack. Mean fertility — tokens per word, more or less — hits one point four three two on Bengali and one point three eight eight on Hindi, well below SentencePiece byte-pair encoding, or BPE. Recursive Semantic Divergence measures expected cumulative semantic disagreement between independent rollouts of the same agent from the same state using natural language inference. As a reward signal it cuts task-progress variation from one hundred thirty-two percent to ninety-one percent on tau2-bench. On toolsandbox that variation falls from ninety percent to forty-four percent. The metric needs no ground-truth labels. It estimates future divergence from the current state. Performance improves across benchmarks and scales. SLICE-Mem uses a compact classifier for salience-guided admission. Total LLM token consumption falls by ninety-two point four percent on one and ninety-nine point five percent on the other. Cross-entry reconciliation is deferred to an offline stage. FlexA-Mem writes each unit of history once into an immutable store. Every call gets a fresh compact timeline plus detail, rendered by a fixed rule that fits remaining budget without an LLM call. Diffusion language models are the setting for TraceQuery, which predicts a small set of near-future trajectory-relevant positions from full-denoising trajectories. It queries only those candidates. Soft-prompt compression paid a quadratic Transformer tax on every extra token, so it is time to pop the hood on the Boa Compressor. Boa replaces that Transformer backbone with a Mamba state-space model that encodes arbitrary-length context in a single linear-time pass. That pass produces a representation which conditions a frozen target LLM. The state-space model is trained by distillation so its compressed representation produces the same next-token logits as the target LLM ingesting the full context. Because the compressor runs online on every query instead of once offline, it removes the latency overhead that previously confined soft-prompt methods to repeated-query settings. At identical compression ratios the approach matches or exceeds prior offline Transformer-based baselines. Compression time drops by roughly an order of magnitude. It continues to scale to sixteen times compression and longer contexts without the quadratic cost that grows with Transformer-based compressors, and without adding per-query overhead. The practical limit appears when the target LLM's own context window becomes the bottleneck rather than the compressor itself. Teams facing repeated long-context queries should test Boa first; teams that compress once and reuse across many queries can still prefer the older offline methods.
