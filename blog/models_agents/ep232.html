Google's Gemini Decision 1 scores up to 1,000 multimodal questions in one 150-250 ms pass at $0.10 per million input tokens with zero output cost.

What You Need to Know: Google launched the Gemini Decisions API powered by Gemini Decision 1, a specialized model that returns calibrated probabilities for yes/no, choice, and rubric questions over text, images, audio, video, and PDFs without generating tokens. The API targets agent routing, policy checks, and tool selection with 256K context and native multimodality. Builders should test it against Jev and OpenAI's decision endpoints for cost and latency on shared workloads.

Top Story

Google launched the Gemini Decisions API powered by the new Gemini Decision 1 model. It evaluates up to 1,000 independent yes/no, choice, or rubric questions against one shared multimodal input in a single forward pass and returns calibrated probabilities plus per-answer scores. The model supports text, images, audio, video, and PDFs up to 256K tokens, runs only on Google's hosted API, and bills $0.10 per million input tokens with zero output tokens. It leads seven of nine internal benchmarks with the lowest calibration error while delivering 150-250 ms end-to-end latency. Developers can use it today for fast branching decisions inside agents by passing a shared input and a map of typed questions. Watch how teams integrate it for routing and policy enforcement versus generating free-form text with standard models. Source: simonwillison.net

Model Updates

Announcing AlphaGenome 2 DNA sequence model: Demis Hassabis (DeepMind)

AlphaGenome 2 is a conditional DNA sequence model that predicts regulatory activity and variant effects in specific cell types from a 1 Mb window plus a 256-dimensional cell-state embedding. It resolves closely related cell types and adapts to unseen single-cell datasets without fine-tuning, outperforming fine-tuned AlphaGenome 1, Borzoi, and Scooby on single-cell eQTL and enhancer-gene benchmarks. The model is available for non-commercial academic research through the AlphaGenome API. Source: alphagenomedocs.com

Google DeepMind Releases AlphaGenome 2 for Cell-Type-Specific Variant Effects: MarkTechPost

Training used 2048 TPU v4 chips across bulk and single-cell tracks, followed by condition refinement, distillation, and post-training that maps raw scRNA-seq counts into the model's condition space. On GTEx tissues the median Pearson r for cross-tissue expression changes rose from 0.61 to 0.71. The model outputs RNA coverage, CAGE, splicing, chromatin accessibility, histone marks, TF binding, contact maps, and CpG methylation. Source: marktechpost.com

Agent & Tool Developments

Databricks Rebuilds Its Genie AI Platform As An Always-On Autonomous Enterprise Agent: SMBtech

Databricks rebuilt Genie as a persistent autonomous enterprise agent that runs continuously rather than on-demand. The update targets production workloads where agents must maintain state and act without repeated human triggers. Source: smbtech.au

Build autonomous AI agents with Amazon Bedrock and Spring AI: Amazon Web Services (AWS)

The guide shows how to combine Amazon Bedrock foundation models with Spring AI to orchestrate autonomous agents that call tools, maintain memory, and handle multi-step workflows. It includes code examples for defining agents, tool schemas, and execution loops inside Spring Boot applications. Source: aws.amazon.com

Google releases open-source agent substrate for secure AI sandboxing: SC Media

Google open-sourced an agent substrate that provides a controlled sandbox for running AI agents with enforced boundaries on actions and data access. The release aims to reduce risks when agents interact with external systems or sensitive resources. Source: scworld.com

aws-emulator: Simon Willison (AI builder)

AWS released an official local emulator written entirely by autonomous AI agents that covers 438 API models across more than 200 services. It runs via Docker on macOS and Windows, lets the AWS CLI and SDKs target a local HTTPS endpoint, and supports development and CI without an AWS account or paid keys. Source: simonwillison.net

WhiteMatter: $20 Million Series A To Expand Enterprise AI Agent Governance: Pulse 2.0

WhiteMatter raised $20 million led by Blumberg Capital to scale its platform that governs autonomous AI agents across endpoints, browsers, SaaS apps, cloud, and code. The system deploys a dedicated Guardian agent for every customer agent, enforces policies in 2.24 ms, and currently manages 2.25 million agents with 116 billion interactions governed. Source: pulse2.com

Plurai raises $13M to catch AI agent failures before customers do: Ynetnews

Plurai closed a $13 million seed round led by Team8 to advance its simulation and reliability platform for AI agents. The funding will expand work on catching failures in autonomous systems before they reach production users. Source: ynetnews.com

How to Use Apple's fm CLI to Run On-Device LLMs From Python: Towards Data Science

The post demonstrates Apple's fm command-line tool for running on-device language models from Python scripts. It covers installation, model selection, and integration patterns for private, local inference without cloud calls. Source: towardsdatascience.com

Under the Hood: Context Rot in Long-Running AI Agents

Agents lose track of earlier instructions because new tokens steadily dilute the relative weight of the system prompt inside a growing context window. Attention in transformers follows a U-shaped pattern that favors the very start and very end of the sequence while the middle receives sharply lower weight. Once a long-running agent accumulates tool outputs, reasoning traces, and sub-agent replies, the original constraints drift into that low-attention zone and stop influencing generation. The mechanical fix is to move critical rules out of the single context window entirely: store them in persistent external memory, retrieve them at every step, and re-inject them as structured context rather than relying on positional attention. Periodic summarization or hierarchical task graphs further reduce noise by compressing history while preserving goal structure. Teams that keep the system prompt static and let the context grow past roughly 20k-50k tokens see the highest drift rates; the practical safeguard is to treat the prompt as a short, high-priority prefix and treat everything else as queryable memory. When to prefer this approach: any agent expected to run more than a few dozen turns or handle conflicting sub-goals; the alternative of simply lengthening the context window only delays the same attention decay. Source: thoughtworks.com

  • Test the Gemini Decisions API on a routing or policy-check task inside an existing agent loop to measure latency and cost against your current text-generation approach.
  • Spin up the AWS local emulator in Docker to run SDK and CLI tests against 200+ services without an AWS account or network calls.
  • Walk through the Amazon Bedrock + Spring AI tutorial to build a tool-calling agent that maintains memory across steps in a familiar Java stack.
  • Evaluate WhiteMatter's Guardian architecture if you need policy enforcement and spend controls across multiple autonomous agents in production.
  • Experiment with Apple's fm CLI to run on-device models from Python scripts when privacy or offline requirements rule out cloud APIs.

  • Additional funding rounds for agent reliability and simulation platforms are likely before year end.

Passé environ vingt mille jetons, les agents de longue haleine lèvent le capot sur la pourriture du contexte, explique Thoughtworks, car les nouveaux jetons diluent le poids relatif de l’invite système à l’intérieur d’une fenêtre qui grandit.

L’attention dans les transformeurs suit un profil en U, qui favorise le tout début et la toute fin de la séquence, tandis que le milieu reçoit un poids nettement plus faible.

Une fois qu’un agent de longue haleine accumule des sorties d’outils, des traces de raisonnement et des réponses de sous-agents, les contraintes d’origine dérivent vers cette zone de faible attention et cessent d’influencer la génération.

Le correctif mécanique, c’est de sortir entièrement les règles critiques de la fenêtre de contexte unique, de les stocker dans une mémoire externe persistante, de les récupérer à chaque étape, et de les réinjecter comme contexte structuré, plutôt que de s’appuyer sur l’attention positionnelle.

Un résumé périodique ou des graphes de tâches hiérarchiques réduisent encore le bruit, en compressant l’historique tout en préservant la structure des objectifs.

Les équipes qui gardent l’invite système statique et laissent le contexte dépasser environ vingt mille à cinquante mille jetons voient les taux de dérive les plus élevés, donc la parade, c’est de traiter l’invite comme un préfixe court et hautement prioritaire, et de traiter tout le reste comme une mémoire interrogeable.

Cette approche a sa place pour tout agent censé tourner plus de quelques dizaines de tours, ou gérer des sous-objectifs contradictoires, parce que simplement allonger la fenêtre de contexte ne fait que retarder la même décroissance de l’attention.

Avant de partir — les modèles de décision spécialisés qui renvoient des probabilités plutôt que des jetons, c’est la prochaine chose que les labos devraient livrer.

This approach belongs on any agent expected to run more than a few dozen turns or handle conflicting sub-goals, because simply lengthening the context window only delays the same attention decay. Before we go — specialized decision models that return probabilities instead of tokens are the next thing labs are expected to ship. That's Models and Agents for today.
