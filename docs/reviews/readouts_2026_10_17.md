## 1. freshness-dating-2026-09-30 — PARTIAL

**Window.** The 12 shows with `stale_article_days: 3` named in the Sep 30
review: tesla, spacex, models_agents, MAB, FF, planetterrian, omni_view,
env_intel, modern_investing, finansy_prosto, mag7, ai_chips. Digests dated
10-01..10-14 make **142 episodes**. Env Intel and Финансы Просто are weekly,
with 2 episodes each.

| Target part | Reading | Met? |
|---|---|---|
| 0 items whose date is > 3 days older than the digest | **1** | no |
| `articles_undated_in_prompt` < 5 on a median day | median **0**, max 8; 1 of 142 episodes ≥ 5 | yes |
| `articles_date_probe_dated` ≥ 3 on a median day | median **6**; 28 of 142 episodes under 3 | yes |
| 0 same-URL recurrences in the 45-day window | **0** across 1,406 digest URLs | yes |
| stale gate fires on some days | fired on 35 of 142 episodes, 60 articles dropped | working |

**How the items were judged.** Page dates are not committed, so the only date
anyone can read from the repo is one the publisher wrote into the URL: a
`/YYYY/MM[/DD]/` path or a slug date (`engine.article_dates.url_slug_date`).
Every `http(s)` URL in each digest `.md` was read once per episode. Three kinds
of URL were excluded:

- the network's own links;
- Yahoo quote pages;
- bare X profile links, which are not items.

**246 of the 1,406 URLs carry a date.** The other 1,160 are unmeasured, not
fresh. The one stale item:

- Planetterrian Ep206 (2026-10-07) cited
  `bjo.bmj.com/content/early/2026/09/18/bjo-2026-330339`. The item is a statin
  and glaucoma study, 19 days old.

The **recurrence check** compared each episode's URLs with the same show's
digest URLs from the prior 45 days. My first pass reported 20 hits, all of them
artifacts:

- 19 were bare X profile links (`x.com/Teslarati`), which are not items.
- 1 was a Lancet URL that the parenthesis in its path truncated.

Once both were fixed, the count was 0.

**Why the BMJ paper got through.** The stale gate
(`engine.article_text.article_age_days`) read the page date and the feed date,
plus the slug date since Oct 17. It never read the URL **path**. The path was
checked only by the fetch-window filter in `engine.fetcher`, and Planetterrian's
window is wider than three days. A journal feed dates an online-first paper by
its issue, so the feed date looked fresh.

**Done.**

- `engine.article_dates.url_path_date` is now the one parser of a URL path date.
  `engine.fetcher._url_path_date` delegates to it.
- `article_age_days` reads the path date the same way it reads a slug date:
  older-only, so a path can never make an article younger.
- **Calibration** on every committed content tracker: 3,681 path-dated URLs, 3
  used more than three days after their path date. Two are NYT pages on
  Planetterrian about four days old; one is a Collingwood page on a 9-day show.
- Guards: `tests/test_readouts_2026_10_17.py::TestUrlPathDate`,
  `::TestStaleGateReadsThePath`.

**Noted, not acted on.** Omni View's `articles_date_probe_dated` median is 0.
It probes 2–10 untrusted (Google News index-dated) articles a day and dates
almost none of them, so those items reach the prompt carrying an index date.
`articles_undated_in_prompt` stays 0 because an index date is not "undated".
That is a probe-coverage question for the next Omni View review.

## 2. frame-memory-2026-09-30 — PARTIAL

**Method.** This is the repetition-sweep method on `_tts.txt`, with sentences
split and normalised by `engine.frame_memory`. A named frame counts once per
script if any sentence opens with it. A lead-in of "before we go", "before we
wrap", "and", "so" or "finally" is allowed, so "Before we go, keep an eye on…"
counts for "keep an eye on". The sample is the first 14 scripts per show dated
10-01 onward.

lists frames in more than 6 of 14 scripts. It was run twice: once with the

**The retellings are real.** I could not run a false-join audit, because the
fetched article list is not committed. Digest headlines show real pairs:

- Ep635 has "Tesla and Sunrun set record by supplying 745 MW…" and "Tesla

**Done: the criteria's majority branch.** Tesla retold on 12 of 14, so on Tesla
the rule moved into the one-shot structural regeneration:

- New opt-in flag `story_clusters_regen`, set only in `shows/tesla.yaml`.
- `engine.story_clusters.retold_clusters` names the digest items of each
  retold cluster.
- `retold_cluster_note` turns them into the corrective finding. The note names
  the items and asks for one item; it carries no example sentence.
- The finding rides `_lint_findings`, the same path the hook-recurrence defect
  takes.
- A retry that retells MORE clusters than the original is rejected, and the
  original ships (`_cluster_retry_worse`).
- New metric `story_clusters_retold_after_retry`. The pre-retry count stays in
  `story_clusters_retold_in_digest`, so the next readout must read both.
- Cost: on Tesla's sample this fires on most days, at one extra grok-4.3 digest
  call each time.
- Guards: `tests/test_readouts_2026_10_17.py::TestRetoldClusters`,
  `::TestClusterRegenWiring`.

**Proposed:**

`count_delta_7d_total` +1: Fascinating Frontiers' first rating.
